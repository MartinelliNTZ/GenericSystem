Da planilha ao laudoOBTERDADOS

Uma pipeline de nove etapas independentes que lê planilhas de campo, valida, calcula e entrega laudos, relatórios e planilhas prontas. Tudo conectado por um único arquivo: o JSON. O SISTEMA (API 00) roda as etapas em três fases: o lote, as OS em paralelo (cada uma no seu JSON) e os consolidados. Por dentro, cada etapa tem as suas subdivisões numeradas (00.1, 00.2, … até 9.4), cada uma com UMA responsabilidade.

Entra, vira JSON, sai pronto

Toda a lógica cabe em três movimentos. As APIs não conversam entre si: cada uma lê o JSON, faz a sua parte e devolve algo.

Entradas

  • Planilhas data/**/*.xlsx
  • Aba de dados e aba Conformidades
  • Laudos PDF/DOCX com “Considerações”
  • Planilha de emissões (aba GHG Data)
  • Banco SQLite de clientes
  • Planilha de notas fiscais (evidências)

JSON central

  • Um arquivo por execução: saida/dados_<ts>.json
  • E um JSON por OS, sobrescrito: saida/OS_131/OS_131_dados.json
  • Árvore padronizada de OS, fazendas e talhões
  • Cada API acrescenta o seu bloco
  • O lote é dividido por OS (fase 2) e, no fim, as OS voltam ao lote (fase 3)

Saídas

  • CSV plano
  • Laudos DOCX e PDF
  • Relatórios HTML
  • Planilha base e planilha de emissões

O fluxo, etapa por etapa

O número da API não é a posição dela no fluxo: a ORDEM é o grafo de tarefas do SISTEMA (API 00). As etapas rodam em três fases: no LOTE (1 → 7 6 5 2 → 0 partição), POR OS em paralelo (4 8 9 → 3, cada OS no seu JSON) e no CONSOLIDADO (4 9 3, os artefatos do lote). Clique em uma etapa para ver o que ela precisa, o que entrega e as subdivisões internas — N.0 é o motor da API (o entry point) e N.1, N.2… as partes internas, na ordem do fluxo; a 00 mostra o próprio sistema.

Rotas: quem alimenta quem

Cada linha é um caminho possível dentro da pipeline. O SISTEMA (00) é a origem de tudo; a API 01 produz o JSON que as demais leem.

Padronizações que mantêm tudo coerente

Poucas regras, aplicadas sempre. É por isso que dá para trocar, testar ou rodar qualquer etapa isoladamente.

Uma OS, um JSON

Na fase por OS o vínculo não é o JSON gigante do lote: é o JSON da pasta da OS, com o mesmo contrato reduzido a ela.

  • saida/<OS>/<OS>_dados.json (nome fixo, sobrescrito)
  • Cada thread carrega só a sua OS: menos memória
  • Nenhuma disputa de arquivo entre as OS
  • No fim as OS voltam ao lote, para o consolidado

Subdivisões numeradas

Cada API é uma caixa fechada por fora e numerada por dentro: N.0 é o motor (entry point), N.1, N.2… são as partes internas.

  • N.0 só lê, chama e grava — a regra de negócio mora nas partes numeradas
  • Onde o código já fixa o número, ele manda: 00.1–00.4, o cálculo 6.1 e as consultas 7.1/7.2
  • Subdivisão nova = arquivo novo + uma linha no registro (CALCULATIONS/CONSULTATIONS) — o motor não muda
  • Subdivisão não importa subdivisão de outra API: o comum sobe para core/ (00.7 a 00.10)

O que você recebe no final

Cinco ramos finais — eles só exibem ou exportam: não decidem nada. Além deles, o SISTEMA (00) deixa o log da execução e o JSON por OS que liga a fase paralela.
